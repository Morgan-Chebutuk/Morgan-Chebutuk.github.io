01. About me

I'm a computer science student at Oklahoma Christian University, graduating in May 2027. Most of what I build starts as a question about structure: how should this data be modeled, where should this responsibility live, and what happens when the requirements change?

That shows up in my work. My point-of-sale system is a Java Swing application split across four packages and 30+ classes, using BigDecimal throughout so tax, split payments, and change never drift by a cent. My maze solver navigates a 3D maze with depth-first search over a custom generic stack, handling portals and dead-end backtracking. My arcade shooter runs a 60 FPS game loop in C++ with an ownership-safe sprite layer over SFML textures.

On the web side I work in JavaScript across the stack — Vue 3 front ends talking to Node and Express APIs, with tests that gate a CI pipeline. I care about correctness, readable code, and tests that actually mean something, and I'm looking for a junior software engineering role or internship where I can learn from engineers who care about the same things.

POS — Point of Sale System

A Java Swing desktop application for running a convenience store end to end: cashier authentication, sale processing, multi-tender payments, inventory with UPCs and promotional pricing, date-effective tax rates, and reporting. Architected as a layered system across four packages and 30+ classes, keeping domain models, data management, and user interface logic strictly separated — with its own acceptance test suite verifying the model.

  • CSV-driven data loading for store setup
  • Five acceptance test suites covering the domain model

Maze Solver — 3D Droid Navigation

A droid drops into a 3D maze knowing nothing but its immediate surroundings and has to find the exit. Solved with depth-first search over a custom generic stack, tracking visited coordinates, handling portals, and backtracking out of dead ends — the classic exercise in making an agent reason from purely local information.

  • Hand-rolled generic MyStack backing the traversal
  • Maze scanning APIs to evaluate adjacent cells and avoid blocked or out-of-bounds moves
  • Portal handling and visited-coordinate tracking
  • Interface-driven design separating droid behavior from maze
