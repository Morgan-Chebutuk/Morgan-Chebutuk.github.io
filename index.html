01. About me

I'm a computer science student at Oklahoma Christian University. Most of what I build starts as a question about structure: how should this data be modeled, where should this responsibility live, and what happens when the requirements change?

That shows up in my work. My point-of-sale system is a Java Swing application split into clean problem-domain, data-management, and UI layers with its own acceptance test suite. My full-stack todo application is spec-driven — written requirements and Gherkin scenarios come first, then Vue 3 and Express code that traces back to them, verified by Jest and Vitest in a GitHub Actions pipeline.

I care about correctness, readable code, and tests that actually mean something. I'm looking for a software engineering internship where I can learn from engineers who care about the same things.

02. Projects

Full-stack · Featured

Spec-Driven Todo Application

A multi-user todo platform built specification-first: written requirements, API contracts, and Gherkin acceptance criteria define the system before any code exists. A Vue 3 SPA talks to an Express API over JWT-authenticated requests, with every query scoped per user — cross-user access returns 404, never leaking existence. Backend tests in Jest and frontend tests in Vitest gate a GitHub Actions pipeline that deploys the SPA and API as independent artifacts.

  • Registration, login, and server-side sessions with bcrypt + JWT
  • Per-user data isolation enforced at the query layer
  • Every acceptance scenario mapped to an automated test
  • CI/CD: tests must pass before either artifact deploys

Point of Sale System

A Java Swing application for running a convenience store: sale processing, cashier sessions, register and cash-drawer management, inventory with UPCs, promotional pricing, and date-effective tax rates. Split into distinct problem-domain, data-management, and UI packages, with a CSV loader and five acceptance test suites covering the model.

  • Layered architecture: POSPD / POSDM / POSUI
  • Polymorphic payments — cash, credit, and check
  • Cashier, item, and daily sales reporting by date

Java · Algorithms

Maze Navigation with Autonomous Droid

A droid drops into a generated maze knowing nothing but its immediate surroundings and has to find its way out. Solved with depth-first traversal over a custom stack implementation, tracking visited coordinates and backtracking on dead ends — the classic exercise in making an agent reason with only local information.

  • Hand-rolled MyStack backing the traversal
  • Interface-driven design separating droid from maze
  • Coordinate tracking and dead-end backtracking
